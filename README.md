# handformer

A transformer that does arithmetic, with **every weight written by hand**.
Nothing is trained. The tokenizer is raw bytes. One set of **8,478 hand-written
weights** evaluates whole expressions with `+ − * / ^`, unary minus, parentheses
and precedence on signed decimal numbers of any length, with division to a
precision given in the prompt (`1/3~5` → `0.33333`). The model writes its own working and its own answer;
the host only feeds bytes and stops at `\n`.

```
$ python -m handformer "2+3*(4-1)" "1+(3-7)*2"
2+3*(4-1)=[4-1=3;3]2+3*3=[3*3=90|90;9]2+9=[2+9=11;11]11
  -> 11
1+(3-7)*2=[3-7=6<-4]1+-4*2=[-4*2=80|80;-8]1+-8=[1+-8=3<-7]-7
  -> -7
3.14*(2-0.5)=[20-05=51;15]3.14*1.5=[314*15=0751,1740|01740;4710]4.71
  -> 4.71
```

Everything after the first `=` is generated by the model. Each `[...]` is one
reduction step: the model chooses the sub-expression by parentheses and
precedence, copies it into a frame, computes it, and writes the reduced line.

## What it does

| | |
|---|---|
| operators | `+`, `-`, `*`, `/` (truncated to `~N` digits), `^` (integer exponents), unary minus, parentheses, precedence, left-to-right order |
| operand length | arbitrary (tested to 300 digits for + and −, 25 for ×; designed for ~10⁶ positions) |
| model | 22 layers, 147 attention heads, 1,044 MLP units, d_model 576 |
| weights | 8,478 nonzero, every one from a documented formula over named residual dims |
| architecture | standard decoder-only transformer: causal multi-head attention + ReLU MLP; no LayerNorm, no biases |
| host logic | none: no parsing, no routing, no reversing, no answer fix-up |

## Everything is in the weights

`tools/run_weights.py` is a ~60-line numpy-only forward pass that never
imports `handformer`. It runs the exported tensors directly:

```
../.venv/bin/python -m handformer.export weights.npz
../.venv/bin/python -I tools/run_weights.py weights.npz "2+3*(4-1)" "1/3~5" "-2^3"
```

The only facts it uses beyond the arrays: the architecture (causal attention
summed over heads, a ReLU MLP, residual adds) and which two input columns carry
position p and p². Dimension and circuit names exist only at build time and
for labelling.

## Visualizer

`python -m handformer.viz` serves a step-through view on port 8768.

- **Step through every byte the model writes** with ← →, play, or by clicking a byte.
- **Sequence strip:** each byte is coloured by the phase that wrote it (open, copy, add, sub, mul, rewrite). The step's pointers are tagged above it.
- **Step panel:** a plain-language reading of the step and the top logits.
- **Attention heads:** every head's read position and what it wrote, plus its hand-written score and value formulas.
- **Residual stream:** the named dimensions, with which sublayer wrote each one.
- **Active MLP units:** each unit that fired, with its formula.
- **Raw weights:** every matrix (embedding, unembedding, W_Q/W_K/W_OV, MLP W_in/W_out)
  as a labelled heatmap, exact values on hover.
- **Heatmaps:**
  - residual stream (dims × positions, after any sublayer);
  - this step (dims × sublayers);
  - the full attention pattern of a head;
  - MLP activations (units × positions).
- **"Focus active circuit"** hides circuits that aren't active at the current step.

Each step's trace is the model's own forward pass, through an observe-only
hook, so the visualizer shows exactly the computation the tests check.

## The ideas that made it work

- **Attention does addressing, not similarity.** Every head answers "which
  position do I read?" A score of `−β(k − t)²`, built from the positional
  features `pos` and `pos²`, picks position t exactly, with the same sharpness
  at any length. Softmax acts as an exact argmax.
- **Positions double as arithmetic.** Gathering `pos²` at position x returns
  x², so x·y = ((x+y)² − x² − y²)/2 is three lookups. A "ruler" head scoring
  `−β(s·k − x + (s−1)/2)²` computes ⌊x/s⌋. Together they tell multiplication
  which line and column the next byte belongs to, without writing any counters.
- **Recover, don't store.** carry = ⌊y/10⌋ + [previous digit < y mod 10]
  recovers the carry from the previous output digit (valid for any carry
  below 10, so it covers ×). Borrows work the same way. The sign of a
  difference is written once, in the end-of-working byte (`;` vs `<`), at
  the moment it is known.
- **A first match after a point, despite causal attention.** Every position
  stores its previous match. The first match after t is the unique match whose
  stored pointer equals the latest match at t, which is a quadratic equality
  score. This is what finds `)`, the next operator and the operand ends.
- **Order of operations without a stack.** Repeated rewriting: innermost
  group (the latest `(`), its `)`, `*` before `+ −`, leftmost first, operands
  as maximal digit runs. Each rule is a fixed number of attention lookups, and
  nesting depth never appears in the circuit.
- **Gating, not routing.** All three operator circuits run on every input. A
  0/1 flag computed in the weights (which operator this frame holds, which
  phase we're in) silences the ReLUs of the inactive ones.
- **Signs as part of the operands.** A `-` is unary when the byte before it
  is not a digit or `)`, which a layer-1 head reads. Circuits work on
  magnitudes. For `+`/`−`, comparing a's sign with b's effective sign routes
  to add-magnitudes or subtract-magnitudes. `-(-v)` cancels in the rewrite,
  and `-0` never appears.
- **Decimals without touching the operator circuits.** The frame copy drops
  each operand's `.` and zero-pads the shorter fraction (`1.25+3.5` →
  `[125+350=…]`). The rewrite puts the point back: it strips trailing zeros,
  inserts `.` f digits from the right and left-pads (`0.1*0.2` → `0.02`).
- **Division without trial subtraction.** Long division in a grid: rows of
  the 9 multiples of the divisor, then quotient-digit + remainder rows. Each
  remainder digit compares itself with all 9 multiples as it is written, and
  9 latest-match heads pick each quotient digit in one pass.
- **Powers by rewriting.** A power frame writes one step of binary
  exponentiation as text: `(a*a^(n−1))`, `(a*a)^(n/2)`, `(1/a^n)`, `1` or `a`.
  The `*` and `/` circuits do the arithmetic. Halving the exponent is
  digit-local.
- **Complement during the copy.** For a negative difference, the model emits
  10ⁿ − D digit by digit while reading D out (9−d, 10−d or 0, depending on
  position), with no second pass.

## Lessons

In a hand-built model the enemies are numerical, not logical. Both real bugs
were found by reading named residual dimensions directly:

1. **Noise amplification.** Selects multiply flags by a large gating constant
   (10⁶), so 10⁻¹² of attention noise became 10⁻⁶. Integer tests with
   breakpoints on the integers passed it through, and a copy landed one byte
   off. Fix: every integer test is a robust step with breakpoints at
   half-integers, so every flag is exactly 0 or 1.
2. **Ties.** A matching start byte tied with a match at position 1, and
   attention averaged the two. Fix: the latest-match feature is 2(pos+1).

## Notes from building it

What made the work easier, and what was most enjoyable:

- **Named residual dimensions.** Writing weights as `{"P": 1, "F": -1, "one": 1}`
  instead of matrix indices made circuits read like the algorithm. It made
  debugging fast: both real bugs showed up in one probe printing `a_lo=0.50`
  (a tie) and `drop=0.9999987` (amplified noise).
- **Positions turned into arithmetic.** `pos²` was added only for sharp
  lookups. Then reading pos² at position x became a table of squares, which
  gave exact products, which gave floor division (the ruler head), which
  removed counters from multiplication. One feature, added for a different
  reason, ended up holding up the hardest circuit.
- **"First match after t" turned out to be solvable.** It looked like
  something causal attention simply can't do. Reframing it as pointer chasing
  (every position stores its previous match) turned the dead end into one
  reusable building block, which unlocked parentheses, precedence and operand
  bounds together.
- **Recover, don't store.** Reading the carry back from the output digit
  removed a whole class of state. That carry = ⌊y/10⌋ + [prev < y mod 10]
  also covers multiplication's carries up to 9 was a nice surprise.
- **An independent reference with teacher forcing.** One forward pass checks a
  whole sequence against a reference written separately from the weights, so
  every refactor was safe. A first-try pass of the expression model could be
  trusted because nothing was shared.
- **Strict constraints led to better designs.** "No flipping at the end" and
  "dispatch sounds like a cheat" led to the in-weight answer copy and
  in-weight operator routing, now the cleanest parts of the design.
- **What to do first next time:** make integer tests robust and latest-match
  features tie-free from day one. Both bugs were numerical, not logical. In a
  hand-built model, the margin between correct and incorrect values is the
  first thing to design for.

## Layout

```
handformer/
  model.py           engine: ModelBuilder (named sparse specs → dense weights), Transformer, cached decoding, trace hook
  primitives.py      gather / latest / next-match / floor-division heads, robust steps, gating, products
  common.py          byte embedding, operand addressing, mod-10 ramps
  frame.py           layers 1–4: unary vs binary '-', markers, frame flags, phases, sign-aware operator routing
  expr.py            layers 4–22: choose the sub-expression, copy it into the frame, rewrite the line
  addition.py  subtraction.py  multiplication.py  division.py  power.py    operator circuits
  export.py          python -m handformer.export weights.npz: every tensor + a JSON index of names
tools/
  run_weights.py     independent numpy-only inference from the exported weights
  arith.py           merges everything into one model; solve()
  viz/               step-through visualizer (FastAPI + vanilla JS)
tests/
  reference.py       independent plain-Python generator of the exact expected byte sequence
  test_ops.py        every a op b for a, b < 40 and signed a, b in -12..12; long operands; edge cases
  test_expr.py       hand-picked and random expression trees; greedy decoding
  test_decimal.py    decimal literal pairs, formatting, long fractions, random decimal trees (exact)
  test_division.py   small/long/signed/decimal quotients at several ~N; random trees with '/' (exact)
  test_power.py      small/large/decimal/negative exponents, precedence, right-associativity (exact)
DESIGN.md            full design: attention, residual stream, order of operations, every circuit
ANSWER_FIRST.md      analysis: can the first emitted byte be the answer? (deferred)
```

## Verification

Every test compares the model byte for byte against `tests/reference.py`,
which is written separately from the weights. Checks are teacher-forced (one
forward pass, the argmax at every output position must equal the next
expected byte). That is equivalent to greedy decoding reproducing the
sequence exactly. A separate test runs real cached greedy decoding.

## Limits and next steps

Not supported yet:
- a prompt with no operator;
- parentheses around a bare number;
- division by zero (undefined); roots and fractional exponents.

Roadmap, in dependency order:
1. ~~signed operands~~ (done);
2. ~~decimals~~ (done);
3. ~~division with precision given in the prompt (`~N`)~~ (done);
4. ~~integer powers~~ (done);
5. square root.

Planned alongside: visualizer readability (each unit labelled by its meaning,
operator steps explained with real numbers, a one-line meaning for every
dimension).

## Why the working is written out

A fixed-depth transformer does a bounded amount of work per emitted token. A
carry chain, n² partial products or nested parentheses need unbounded
sequential work, so the model writes its working and reads it back, which is
the same move as a language model's chain-of-thought. Everything that fits in
one pass (addressing, position products, division, pointer chasing, carry
recovery) is done in the residual stream instead. See `ANSWER_FIRST.md` for
what it would take to skip the working entirely.
