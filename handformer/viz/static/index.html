Guide: the landmarks and tricks this model uses, and how to see each one here

Every weight is written by hand, so every value has one meaning. The model works in steps: at = it opens a frame [, copies the piece it will solve next, works it out, closes with ], and writes the simpler line. Each byte it writes is one pass through all 22 layers. Use Step ▶ (or ← →) to walk through them.

Landmarks (the orange tags above the bytes)

A landmark is a position the model keeps as a number. The tags show where each one points at the current step; hover or tap a byte to read them, or see them all in the Pointers box.

Lsstart of the line being reduced (the ] before it)
[ F · ] Rb · = E · ; Slatest [, ], =, and ;/<: together they say which job the model is doing (open a step, copy, calculate, rewrite)
p · cthe innermost group: its ( (or the line start) and the first ) after it
othe operator solved next: latest ^, else first * /, else first + − — that is the precedence rule
a_lo · b_hithe bytes just outside the two numbers around o: they fence the piece that is copied into the step

How it finds the latest X: an MLP unit tags every X byte with 2·(position+1); an attention head scores keys by that tag, so the newest X wins and the head copies its position. The start byte scores 1, so "none yet" reads position 0. In the attention map the blue line climbs to each new [ and stays there.

Tricks with attention

  • Exact lookup: the score −30·(key − t)² peaks at one position t that this byte computed, so the head reads exactly that byte (a digit of an operand, the byte to copy).
  • Forward search: causal attention can only look back, yet c needs the first ) after p. Each byte stores where the previous match was; the target is the one match whose stored pointer equals the latest match at p.
  • Products from a table of squares: reading pos² at position x gives x², and x·y = ((x+y)² − x² − y²)/2. Multiplication uses this to find where each line of working starts.
  • Division by attention: floor(x/s) is the one position k where s·k is closest below x; one head finds it.

Tricks with MLP units

  • Exact yes/no steps: a pair of ReLUs makes clamp(4·(x − ½), 0, 1). For a whole-number input that is exactly 0 or 1, even with ¼ of noise, so flags can safely switch other units on and off.
  • Gating, not dispatch: every calculator runs at every byte; its outputs are silenced (−10⁶ on their input) unless its act_… flag is 1. Focus active circuit hides the silenced ones; untick it to see all 147 heads.
  • The carry is recovered, never stored: carry = [y ≥ 10] + [y = 9 and the previous output digit is 0]. The working is written least-significant digit first so the carry can be read back.

The written text is the memory

Within one byte, everything happens in the residual stream. Across bytes, the only memory is the text: the parser copies the piece into the frame, the calculator reads those bytes and writes its result, and the rewrite copies the result back into the line. The parser and the calculators share no values at all.

Check an explanation yourself

  • Knock out a head, unit or value (buttons on the selected head, an opened value, every active unit) and re-run: if it matters, the answer changes. (47+38 becomes 75: the carry from 7+8 is gone). With a knockout on, the heatmaps show change vs normal: the cells it alters, at every layer and position, i.e. its footprint.
  • Share a view: 🔗 link copies a URL that reopens this exact view, knockouts included.
  • View source (file.py:line ↗ links) opens the Python line that wrote any head, unit or value; Raw weights shows the numbers themselves.
